# VulkanScope Database 0.39.3 GitHub Actions / source-audit hardening

## Root cause addressed

A GitHub Actions checkout necessarily contains a repository-owned top-level `.git/` directory. Source verification must treat this as checkout metadata, while the deployable Pages artifact must remain completely free of VCS/development material.

## Requirements

- Source-tree traversal must prune root `.git` before recursion rather than recursively entering it and filtering individual files afterward.
- A nested `.git` directory anywhere else remains forbidden and fails the source audit.
- The audit command supports an explicit `--source-tree` mode and prints its own version with `--version`, so stale CI scripts are immediately visible in logs.
- GitHub Pages continues to deploy only an allow-listed `_site` tree.
- `_site` artifact verification fails closed on `.git`, `.github`, worker/tools/rules content, build/cache/dependency material, symlinks, unexpected top-level entries, or broken local resources.
- Current GitHub-hosted action majors are used: checkout v7, setup-python v7, configure-pages v6, upload-pages-artifact v5, deploy-pages v5.
- Checkout credentials are not persisted because the build/deploy workflow does not push Git changes.
- Build job permissions are read-only; Pages/id-token write permissions exist only on the deploy job.
- `upload-pages-artifact@v5` uses `include-hidden-files: true` so the explicitly allow-listed `_site/.nojekyll` survives upload. No other hidden repository data is staged into `_site`.
- Database/report schemas, D1 data, report ids/hashes, normalizer 15, VulkanScope 0.41.5 producer semantics, filters/statistics and hash routes are unchanged.

- Automated audit hygiene regression tests verify root checkout metadata acceptance and nested/artifact `.git` rejection.

- Source verification rejects extra `.github/workflows/*.yml`/`.yaml` files so an obsolete workflow cannot continue running independently.
- The distributed ZIP is laid out at repository root (not inside an extra version directory) so extraction directly over the repository replaces `tools/` and hidden `.github/` paths instead of creating a nested project.
