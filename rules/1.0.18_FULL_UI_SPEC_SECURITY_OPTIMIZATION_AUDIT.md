# VulkanScope Database 1.0.18 full UI / specification / security / optimization audit

## Release identity
- Database: 1.0.18
- Immutable predecessor: VulkanScope Database 1.0.17
- Predecessor ZIP SHA-256: `4279690b5c88d14747528b9a4e4d14eca695d3946743d9af66a5f51ada4264e2`
- Producer/query baseline: VulkanScope 1.0.19 / Vulkan 1.4.362
- Locked Vulkan registry/header: Vulkan 1.4.362 / header 362, published 2026-09-04
- Submission schema: 2
- technicalReport schema: 3
- Normalizer: 16
- Database storage migration: none

## Requested UI repairs
1. Paged Coverage Reports and Distinct/value dialogs retain bounded scrolling and 10/25/50 paging, but the page-size custom selector is now explicitly enhanced as a compact drop-up. Its option menu is anchored above the trigger so it stays inside the usable dialog region instead of protruding/clipping below the modal footer.
2. Android filter artwork uses the Android online brand green `#3DDC84` with dark-neutral detail `#202124`; the previous Vulkan-red recolor is removed and CSS preserves intrinsic SVG fills.
3. Devices now has a Statistics/Versions-style circular GPU/report distribution above a separate exact-count table. The table keeps bold GPU name, vendor logo, canonical vendor/family/raw-ID display, maximum device API, driver variants, report count and share. The chart is explicitly report distribution, not hardware or market share.

## Correctness / Vulkan specification review
- The bundled registry lock remains `apiVersion=1.4.362`, `headerVersion=362`, publication date 2026-09-04 and 476 registered extensions; no registry/query corpus was widened by this Database-only release.
- Registry metadata is not promoted into runtime capability evidence. Support/availability/Not applicable/Unknown semantics, coverage dominance/hatching, report provenance and raw GPU vendor-ID provenance remain unchanged.
- VulkanScope 1.0.19 remains the producer/query floor represented by the Database metadata. Schema 2, technicalReport 3 and normalizer 16 remain locked.

## Crash / error / security review
- Current frontend, Encyclopedia JavaScript, Worker source and Worker contract are syntax-checked by release gates.
- All Python tooling is compiled in-memory by the current source audit so syntax failures are release-blocking without leaving pycache artifacts.
- Existing route/compare/Worker contract tests execute when Node is available; D1 migrations replay into an in-memory SQLite database and the payload-chunk table is required.
- CSP remains self/fixed-origin only with `object-src 'none'`, `base-uri 'none'`, `form-action 'none'` and `frame-ancestors 'none'`.
- Dynamic code execution primitives (`eval`, `new Function`, `document.write`) remain forbidden in the frontend.
- Worker request ingestion remains bounded at 2 MiB, strict/fatal UTF-8 decoding remains required, sensitive-key filtering remains enabled, and canonical serialization/security headers remain regression-checked.
- Wrangler is pinned to 4.130.0; sharp is overridden to 0.35.4. The deploy path retains the lock-backed `npm audit --audit-level=high` gate and reviewed install-script allow-list.

## Optimization / resource review
- Modal paging keeps at most 50 evidence rows visible at one time and scrolls the bounded list rather than allowing unbounded dialog growth.
- Devices statistics are computed from already loaded/filtered reports; no new network endpoint or duplicate report-payload fetch is introduced.
- Live synchronization retains the existing bounded 10-second index polling and missing-report-only fetch behavior; this release does not add another timer or polling channel.
- Staged GitHub Pages artifacts are exact allow-list outputs and may not contain source tooling, Worker code, regressions, registry sources, node_modules or stale versioned frontend assets.

## Release gates
The 1.0.18 release requires the current full verifier, targeted negative mutations, comprehensive source audit, staged Pages artifact audit, predecessor regression contract, D1 replay, Worker contract tests and deterministic clean-extract package verification. Local/source audit results do not claim a live Cloudflare deploy or remote D1 smoke test unless those are separately executed.
