# VulkanScope Database 0.39.14 Existing-Repository Overlay Regression Audit

## Confirmed failures in 0.39.13
- A long-lived Git checkout containing legitimate historical files absent from the compact 0.39.12/0.39.13 release ZIP produced `unallowlisted new file` errors even though those files were not introduced by the release.
- Overlay extraction cannot delete `assets/app.v03912.js` / `assets/app.v03913.js`; source audit correctly rejects multiple versioned app assets, so repository repair must be an explicit pre-gate step.
- `build_index.py` changes generated `data/index.json`, including `generatedAt` and report inventory, while 0.39.13 treated the file as a fixed successor hash.

## 0.39.14 contract
- Source-overlay regression mode hashes and protects predecessor-owned files but tolerates unrelated pre-existing source/history files.
- Strict-package mode rejects any file outside predecessor + explicit successor allow-list.
- `data/index.json` is validated semantically.
- Repository repair removes stale versioned app assets and stale workflows only when explicitly invoked with `--apply`.
- Permanent fixture proves all of these behaviors and proves an immutable predecessor file still cannot be changed.

No Worker, D1, API, schema, report-hash, privacy, timeout, Vulkan capability or stored-report semantics changed.
