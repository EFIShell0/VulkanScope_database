# VulkanScope Database 1.4.0 submission / Settings / address-mosaic / startup-filter audit

Database 1.4.0 is the successor to immutable Database 1.3.10 (`3f9932e9661ec93398c6a608234597c1c1fbf20ab2a97bf93dd87364ffdf3581`). The release changes the new-submission producer floor and four requested UI behaviors without rewriting D1 data, stored reports, report hashes, normalizer semantics or Vulkan evidence.

## Changes audited

- Worker POST admission now requires VulkanScope 1.4.0+; 1.4.0 is valid at the floor, while historical reports below the floor remain GET-readable.
- Settings tabs are ordered Favorites → Preferences → Internet → Information and Favorites owns the initial tab state.
- Observed IPv4/IPv6 values start visually mosaicked. Each observed family can be revealed and remasked by clicking; leaving Internet or closing Settings restores the mosaic, and changed observations reset reveal state. Unobserved families are not fabricated.
- The report filter container ships with the HTML `hidden` state so native/legacy filters cannot flash while the current report set is still loading. Existing render ownership unhides the enhanced filter workspace only when the active view is ready.
- Current cache-busted assets are the v1400 JS triplet plus `site.v1400.css`; the 1.3.10 JS triplet is the one-release bridge.

## Verification

The release-specific verifier checks all four contracts, release identity, Worker floor metadata, reduced-motion mosaic behavior and retention of the 1.3.10 searchable regional-selector contract. The negative-mutation suite proves that floor, order, mosaic state/CSS, startup hiding and release-marker regressions are rejected.
