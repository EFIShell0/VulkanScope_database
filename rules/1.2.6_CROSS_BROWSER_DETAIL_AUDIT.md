## Scrollbar finding and fix

- `scrollbar-width` and `scrollbar-color` are the standards-based scrollbar styling surface. They style viewport/internal track and thumb but do not provide a portable stateful native arrow-button contract.
- `::-webkit-scrollbar-*` (including `::-webkit-scrollbar-button`) is non-standard. Depending on it for top/bottom arrow state cannot satisfy Chromium + Firefox + Safari consistently.
- `::scroll-button()` provides real stateful generated scroll buttons in Chromium 135+, but it is not a cross-engine baseline for current Firefox/Safari.
- Therefore Database 1.2.6 replaces only the *viewport* browser scrollbar chrome after application initialization with a same-origin DOM rail. Internal scroll containers keep their established scrolling semantics.
- Endpoint state comes from `document.scrollingElement` plus the maximum of document/body scroll heights and is re-synchronized on scroll, resize and body ResizeObserver updates.
- At absolute top the UP control is explicitly disabled and gray. At absolute bottom the DOWN control is semantically disabled but intentionally remains Vulkan red, matching the requested presentation.
- Thumb drag, track paging, arrow-button paging and keyboard Home/End/Page/Arrow controls are supported. Native wheel, touch and keyboard document scrolling still drive the same document and update the rail.

## Report detail workspace

- Report detail is reorganized into a dedicated evidence workspace instead of the old generic metric strip.
- The canonical Report ID is rendered in full (all 64 hexadecimal characters) in a full-width identity row and again in Overview, with a copy affordance that copies exactly the canonical ID.
- Submission, application, Android device, GPU/driver and Vulkan/collection metadata are grouped by purpose without changing evidence semantics.
- The Back control is larger, styled consistently, sticky within report detail, and remains available across every detail tab.
- Detail tabs remain horizontally scrollable/sticky on narrow layouts; report IDs wrap rather than truncate.

No D1 schema/migration, report payload/hash, report ID generation, normalizer, Vulkan registry baseline or new-submission producer floor is changed by this release.
