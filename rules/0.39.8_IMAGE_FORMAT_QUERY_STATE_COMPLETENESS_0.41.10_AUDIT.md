# VulkanScope Database 0.39.8 Image Format Properties2 complete tuple-state / VulkanScope 0.41.10 audit

## Trigger
A cross-producer comparison could still show an older successful `VK_FORMAT_S8_UINT · LINEAR/OPTIMAL · ANDROID_HARDWARE_BUFFER` row against `Unknown / Not reported`. VulkanScope 0.41.9 preserved explicit non-success results but did not make the separated dataset a complete schedule ledger, so absence could still be ambiguous.

## Correction
VulkanScope 0.41.10 reports a bounded exact tuple-state ledger for every scheduled format and both tilings across base, OPAQUE_FD and Android Hardware Buffer variants. Database 0.39.8 normalizes that ledger separately from normal properties, keeps successful full payloads authoritative, and overlays only non-available states in Compare.

## State contract
- `available`: exact query returned `VK_SUCCESS` / 0 and a matching successful detailed-property payload exists.
- `unsupported`: exact query returned `VK_ERROR_FORMAT_NOT_SUPPORTED` / -11.
- `unavailable`: exact query returned another non-zero `VkResult`.
- `not_applicable`: an external-handle query was not scheduled because its prerequisite extension was not enumerated; `VkResult` is null and the exact prerequisite reason is preserved.
- Base Image Format Properties2 queries are never Not applicable.

## Completeness validation
For 0.41.10+ producers the Worker requires canonical unique tuple names and exactly six slots per scheduled format: LINEAR and OPTIMAL, each with base, OPAQUE_FD and ANDROID_HARDWARE_BUFFER. The ledger is cross-checked against the fixed query recipe and aggregate attempted/success/format-not-supported/other-error counters. Available ledger rows must match successful detailed-property rows and non-available rows must not conflict with successful property evidence.

The structural bound remains safe: the VulkanScope catalog has 298 known format candidates, yielding at most 298 × 2 × 3 = 1788 tuple states under this fixed recipe, below the Database 4096-entry bound.

## Compare and totals
The complete ledger is excluded from Properties & Limits property/query totals. Available ledger rows do not overwrite their corresponding full successful property payload. Unsupported, Unavailable and Not applicable states compare under the same canonical Image Format Properties2 tuple key. Missing evidence from historical producers remains Unknown rather than being inferred.

## Compatibility
Submission schema 2, technicalReport 3, normalizer 15, D1 schema, report IDs/hashes, compatibility floor 0.32.4+ and Vulkan 1.4.360 remain unchanged. Historical 0.41.9 and 0.41.8 producer semantics remain version-gated and accepted.
