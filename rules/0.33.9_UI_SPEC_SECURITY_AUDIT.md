# VulkanScope Database 0.34.0 UI / specification / security audit

## Scope
- Base: 0.33.8.
- Producer compatibility: VulkanScope 0.32.5 schema-v3 structured technical reports.
- No Vulkan technical state or raw report value is changed by this UI release.

## UI
- GPU model names are strongly emphasized consistently in report-backed tables.
- Main-view switching uses opacity/translate only; no height/width/layout animation is introduced.
- Rapid view changes are token-gated and reduced-motion is respected.
- Mobile report-detail tabs retain a 104 px sticky offset for the two-row top bar.

## CapsViewer parity
- Rechecked the current open-source Vulkan Hardware Database tree: reports/devices, Vulkan version support, Core 1.0-1.4 properties/features, extension properties/features, device/instance extensions, instance layers, linear/optimal/buffer formats, memory, queue families, Surface formats/present modes/transform/composite-alpha/usage, profiles, portability and compare are represented by existing VulkanScope Database views or report detail.
- No new category was inferred from names alone.

## Specification/data integrity
- Canonical Vulkan tokens remain unmodified; raw masks remain authoritative and exact-width U64 strings remain preferred when supplied.
- Missing/unqueried data remains Unknown rather than Unsupported.
- Database continues to display the producer's validated Vulkan 1.4.360 baseline; this UI release adds no new enum mapping.

## Security/performance
- CSP/no-third-party-script posture unchanged.
- Worker JSON-only submission, payload bounds, schema/application identity checks, complete-collection gate, parameterized D1 statements, SHA-256 IDs and no-IP-persistence rules remain.
- Main-view animation is compositor-friendly and does not re-run render logic more than once per committed view switch.
