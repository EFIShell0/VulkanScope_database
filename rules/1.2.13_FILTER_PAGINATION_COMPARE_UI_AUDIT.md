# VulkanScope Database 1.2.13 — filter pagination / Compare direction / UI regression audit

## Requested corrections
- Searchable filter/listbox results now use real pages of **50 options maximum** after applying the local search query. Previous/Next and Page X of Y controls navigate the complete matching set without truncating the native selector data.
- Search resets pagination to page 1. Opening a selector keeps the current selected option reachable by opening on its containing page when practical. PageUp/PageDown and boundary Arrow navigation can move between option pages.
- Compare direction is state-correct: full header → downward chevron / Minimize; minimized header → upward chevron / Expand. Unpin/reset restores the full/down state.

## Full UI/bug review findings and hardening
- The inherited `.custom-select` 190 px minimum could still become an overflow source in narrow or newly introduced selector contexts even though current filter families had view-specific overrides. 1.2.13 caps enhanced selectors to their container and removes that minimum at <=760 px.
- Long custom-option labels could enlarge flex content inside narrow dropdowns. Option content now participates in `min-width:0` containment and the visual label is ellipsized without mutating the native option text/value.
- Pager controls use full labels on desktop and compact icon controls on narrow layouts so the pagination footer itself cannot become the next overflow source.
- Existing fixed Compare/listbox collision suppression, Settings overlay layering, Compare identity wrapping and <=900 px filter-family containment remain unchanged and regression-gated.

## Semantics / security
Presentation, navigation and bounded-DOM changes only. Search runs locally against the complete native option set. No new network request, dependency, D1 migration, stored payload rewrite, report hash rewrite, Vulkan evidence inference, denominator change or producer-floor change is introduced.
