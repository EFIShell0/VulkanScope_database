# VulkanScope Database 1.4.2 startup-layout / address-privacy UI audit

## Scope

Database 1.4.2 is a presentation-only successor to immutable Database 1.4.1 (`76888732b4e64273f9a0d0df9d45305577b28a242b1d4aca1bd75c83da875bf7`). It does not alter D1 schema, stored report payloads, hashes, report identifiers, normalizer 16, Vulkan 1.4.362 metadata, report admission, or the VulkanScope 1.4.0+ submission floor.

## Startup layout correction

- `index.html` enters both `database-loading` and `startup-layout-hold` before browser JavaScript runs.
- The hold suppresses unstable application chrome/content while retaining the centered Database loading surface.
- The application performs report assembly, filter initialization, route application and the first committed `render()` before `finishStartupLayout()` removes the hold.
- Fatal startup also releases the hold before showing the fatal-error presentation, preventing a permanently hidden application.
- Reduced-motion users receive the same state transition with no decorative startup animation.

## IP privacy presentation

- Active/IPv4/IPv6/pseudo slots remain independent and are remasked on Internet-panel exit or relevant address changes.
- Each observed address uses a shield/status tile, address-family accent, opaque mosaic layer and eye Show/Hide action.
- Masking is local CSS presentation only. No address is copied to storage or sent to a third party by the privacy control.
- Unobserved IPv4/IPv6 values stay explanatory text rather than fake controls.
- `prefers-reduced-motion` disables the mosaic sheen/transitions without revealing masked text.

## Release identity

Current browser assets are `app.v1402.js`, `browser-compat.v1402.js`, `release-bootstrap.v1402.js`, and `site.v1402.css` with cache key `1402`. The v1401 JavaScript triplet remains as the only immediate predecessor JavaScript bridge.

## Mandatory verification

`tools/verify_1_4_2_startup_layout_address_ui.py` and `tools/test_1_4_2_startup_layout_address_ui_negative_mutations.py` are release gates in source, Pages and strict-package flows, in addition to the project-wide audit, Worker contract, migration replay and immutable predecessor regression contract.
