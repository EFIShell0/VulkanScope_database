# VulkanScope Database 0.39.0 Filter / Statistics Full Audit

## Scope

This audit covers the 0.38.0 → 0.39.0 Database frontend against `rules/PROJECT_RULES.md`, with emphasis on view-scoped filtering, aggregate semantics, Statistics donut charts, current VulkanScope 0.41.4 compatibility, accessibility, responsive design, report integrity and release packaging.

## Filter architecture

- Added exact cohort filters for driver version and enumerated device-extension token in addition to the existing vendor, GPU, Vulkan API, driver mode, device type, Android, ABI, application version and submission-date controls.
- Hidden cohort controls no longer participate in `filteredReports()` for views where they are not applicable.
- Display/HDR remains intentionally isolated from Vulkan GPU/vendor/API/driver/extension filters and uses only directly relevant Android/display metadata. Preferred wide-gamut color space and exact display-mode filters are included; global search on this view is restricted to device/display evidence.
- Properties and Limits use query-state filters and no longer display meaningless Supported/Unsupported aggregate columns.
- Properties/Limits add value-behavior filtering and row search.
- Features add core/extension grouping, row search and support-coverage filtering.
- Formats add linear/optimal/buffer grouping, exact canonical format-feature-bit filtering, row search and coverage filtering while preserving 64-bit mask strings. Explicit zero masks remain direct zero-bit evidence; when a required bit is selected, row state counts describe that bit rather than generic format support.
- Memory adds exact canonical memory/heap flag filters while preserving Unknown when memory enumeration evidence is absent.
- Queues add exact family, queue flag, presentation-state, Vulkan Video query-state, video-codec operation and minimum-count filters. Generic support-state filtering is hidden until a concrete queue capability is selected.
- Surface adds subgroup-specific exact value/token filters and hides the mixed generic state filter on the All view.
- Device extensions add KHR/EXT/vendor namespace, row search and enumeration-coverage filters.
- Instance data adds instance/detail grouping, namespace filtering for extensions and row search across extension/layer metadata.
- Profiles add revision, row search and pass-coverage filtering.
- Devices add sorting and minimum-report controls; Versions now supports Device API, Loader/instance API and paired distributions.
- Compare adds exact section and field-text filtering.
- Clear filters resets applicable global and active view-local controls and restores default view grouping/sorting, including Reports sort and Properties/Features/Formats/Memory/Queues/Surface/Instance subgroups.

## Statistics improvements

- Donut charts now cover GPU vendor, Device Vulkan API, Loader/instance API, physical-device type, driver mode, Android version, application ABI and VulkanScope producer version.
- Each donut category is mutually exclusive within one report.
- Named slices and legend entries are keyboard/mouse actionable, expose active state with `aria-pressed`, apply the matching exact cohort filter, and toggle the same slice to clear it.
- High-cardinality charts use a selectable 5/8/12-slice presentation budget and combine the trailing categories into an explicit Other slice.
- Extension membership remains a frequency ranking because extensions overlap. It supports device/instance/both scope, namespace, minimum enumeration-share and text filters.
- All chart percentages are explicitly filtered-submission shares, never market share.
- Charts remain first-party local SVG/CSS with no remote chart runtime, analytics, fonts or services.

## Compatibility and integrity

- Current producer/query baseline remains VulkanScope 0.41.4 / versionCode 414 and Vulkan 1.4.360.
- Submission schema 2, technicalReport schema 3 and Worker normalizer 15 are unchanged.
- No D1 migration, stored payload rewrite, report hash rewrite or capability inference is introduced.
- Worker request/body/privacy/CORS/D1 protections are unchanged.
- Worker compatibility date remains the deployment-verified 2026-08-23 date.

## Validation

Release validation requires JavaScript syntax checks, route contract tests, Worker contract tests, JSON/HTML local-resource checks, filter-matrix invariants, Display/HDR filter isolation, semantic query-state checks, first-party Statistics checks and package-hygiene checks to pass from the packaged source tree. A headless Chromium interaction harness additionally exercises representative filter changes, Display-only dimensions and search guidance, zero-mask Format semantics, queue family/presentation/video-query filtering, extension-statistics scope, default-group reset behavior and donut slice apply/clear behavior.
