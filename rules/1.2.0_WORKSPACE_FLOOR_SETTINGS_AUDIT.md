# VulkanScope Database 1.2.0 workspace / submission-floor / Settings audit

## Scope
Database 1.2.0 advances from immutable 1.0.25 without a D1 migration, stored-payload rewrite, hash/ID rewrite, normalizer bump, registry change or capability-state semantic change.

## Submission boundary
The Worker rejects every new VulkanScope POST older than 1.2.5 before generic validation. 1.2.5/1205 and newer still pass the complete existing schema, identity, registry, completeness, privacy and payload-size checks. Historical stored reports remain readable through GET/Compare.

## Settings and country controls
Automatic Internet observations are silent after initial data is available. Country options use English UI names, bundled local PNG flags and a wide/wrapping accessible custom listbox while the native select remains authoritative. Informational Settings callouts are blue with an information icon; warnings are amber with a warning icon.

## Workspace redesign
Reports remains the intentionally report-centric baseline. Every other primary view has a purpose-specific workspace context and only applicable global filter families. Surface, Compare and Encyclopedia keep their distinct WSI/comparison/reference semantics. No UI grouping changes evidence state, source values or inference rules.

## Regression gates
The release verifier checks release/cache identity, producer floor, historical-read compatibility, silent network refresh, 250 local country flags, country-selector flag rendering, Compare version emphasis, all non-Reports workspace metadata, filter-family grouping, Settings semantic callouts and predecessor immutability.
