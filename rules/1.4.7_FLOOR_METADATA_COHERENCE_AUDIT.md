# VulkanScope Database 1.4.7 — producer-floor metadata coherence audit

Database 1.4.7 succeeds immutable 1.4.6 (`e54955193140fffa56d0bddec96544074419567327b122b18fb0545ba5c1478c`). The Worker admission floor remains VulkanScope 1.4.3+ and no report/D1/Vulkan evidence semantics change.

## Corrected failure class
The 1.4.6 source correctly raised the Worker floor and static index metadata to VulkanScope 1.4.3, but the frontend accepted `producerQueryBaseline` / `compatibleProducer` from the first live `/v1/reports` response without a release-level floor. GitHub Pages deployment is independent from live Cloudflare Worker deployment, so an older deployed Worker could still return 1.4.0 metadata and visually downgrade the home metrics even while Pages itself was current. Deploy-time preload generation could likewise inherit the stale `compatibleProducer` string.

## 1.4.7 contract
- The frontend owns the visible 1.4.3 producer/query baseline and compatible-producer strings for this release. Old live Worker metadata cannot lower those cards.
- Preload manifests pin both producer baseline fields to the 1.4.3 release contract rather than copying them from the live API.
- Worker source still enforces 1.4.3+ and publishes matching metadata; historical stored reports remain readable.
- Live Worker deployment is operationally separate from Pages/Git release. The source package does not claim the remote Worker is updated until `wrangler deploy` actually succeeds.
- Current cache-busted assets are the v1407 JS triplet plus `site.v1407.css`; v1406 is the immediate JavaScript bridge.
