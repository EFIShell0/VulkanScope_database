# VulkanScope Database 1.0.22 atomic current-set / Settings audit

## Failure addressed
Database 1.0.21 hydrated the deploy-time preload directly into the visible report Map, then reconciled the live Worker index and described missing entries as additional/new payloads. Although foreground refresh already used an atomic replacement, initial loading could visibly present the implementation as a snapshot followed by “+N” live payloads rather than one current Database set.

## 1.0.22 data-flow correction
- Preload chunks hydrate into a private `snapshotReports` staging Map only.
- The authoritative live cursor-safe report index defines the target ID set when online.
- Matching snapshot objects are reused, missing current objects are fetched no-store, exact cardinality is verified, and only then are `state.reports` and `state.index` committed.
- The visible loading model is one `X of N reports ready` current set. Delta fetches remain an internal transport optimization for foreground live sync and do not become additive public state.
- A complete validated preload remains a fail-soft atomic fallback if the live index cannot be reached.

## Local UI state
Favorites and Submitted/Vendor/Type default-expansion preferences are stored only in browser local storage. Favorites are validated report IDs, bounded, and never become report fields, D1 rows, report hashes, or statistics.

## Settings / network information
The new left-side Settings drawer contains Favorites, local clock/time zone, persistent report-column defaults, and a current connection panel. `/v1/network-info` is GET-only/no-store and reads only allow-listed request/Cloudflare metadata. It performs no D1 operation. The UI explicitly reports unobserved address families and DNS resolver identity as unavailable/not observable rather than inferring them.

## Pointer-selection safety
Report navigation now tracks primary-pointer drag/selection gestures in capture phase and suppresses only the immediate navigation click after selection. Explicit interactive controls remain excluded from the gesture guard.

## Immutable boundaries
No D1 migration, stored report rewrite, report ID/hash change, Vulkan evidence semantic change, producer-floor change, normalizer bump, analytics, third-party script, or external IP service is introduced.
