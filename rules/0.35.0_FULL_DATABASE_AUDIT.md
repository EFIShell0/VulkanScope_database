# VulkanScope Database 0.35.0 full audit

Audit scope: project rules, frontend rendering/state, compatibility parser, Worker API/D1 path, schema validation, security boundaries, current Vulkan/Android semantic mappings, responsive/accessibility regressions, and 0.34.9 behavior preservation.

Concrete fixes:
- Compare now uses `gpu.deviceType` and `vulkan.loaderInstanceApiVersion`.
- Footer/version metadata corrected to 0.35.0.
- Property/limit false/zero values no longer become Unsupported merely because their scalar value is false/zero.
- TXT fallback parses `videoCodecOperations` and registry coverage.
- Memory fallback rendering no longer escapes generated flag markup as literal text; canonical text is used where markup is not appropriate.
- Worker normalizer bumped to 8.
- POST body read is streaming and byte-bounded at 2 MiB.
- Worker validates nested submission object shape and schema-v3 technicalReport when present.
- Equivalent submission objects use stable key-sorted canonical JSON for SHA-256 deduplication; canonicalization rejects excessive nesting.
- Frontend detail-fetch failures are counted visibly instead of being silently omitted.
- Preferred wide-gamut label clarified to avoid implying measured panel gamut.

Specification check:
- Khronos public latest checked against Vulkan 1.4.358 (2026-07-31). VulkanScope's 1.4.360 value remains explicitly a producer/query catalog baseline, not a claim about the current published Khronos latest.
- Display-P3 and DCI-P3 remain distinct Vulkan color spaces.
- Android HDR type mapping remains aligned with API 37, including HLG+ value 6.

No claim is made that static auditing proves the absence of every possible vulnerability or runtime defect.
