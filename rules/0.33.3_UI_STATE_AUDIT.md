# VulkanScope Database 0.33.3 UI State Audit

## Report-detail tabs
- `state.detailTab` is the single source of truth for report-detail selection.
- Active visual state, `aria-selected`, and tab focusability are synchronized after every selection and before every detail-body render.
- A tab that is no longer selected must never retain `.active`.
- The newly selected tab is scrolled into the nearest visible position for narrow/portrait layouts.
- Opening a report from Reports or coverage links starts at Overview; returning to the database does not invent or infer a different tab.

## Regression scope
- Main navigation still re-renders from `state.view`; no stale active-state path was found there.
- Select-based Properties/Features/Formats/Memory/Queues/Surface/Instance grouping derives its selection directly from state on re-render and does not use persistent `.active` button classes.
- No Vulkan capability, canonical decoding, status semantics, report normalization, or transport behavior was removed or weakened.
