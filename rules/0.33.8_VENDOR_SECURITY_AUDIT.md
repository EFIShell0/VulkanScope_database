# VulkanScope Database 0.33.8 vendor / security audit

## Scope

- Base: VulkanScope Database 0.33.7.
- Producer compatibility checked against VulkanScope 0.32.5. Its structured technical report remains schema v3 and its registry/query manifest reports Vulkan 1.4.360.
- Vulkan capability semantics, canonical/raw value handling and status-state rules are unchanged from 0.33.7.

## GPU vendor artwork

- Reused the vendor artwork already bundled with the VulkanScope Android application.
- Web copies are local 128x128 PNG derivatives to reduce transfer and decode cost.
- Mapping prefers canonical Vulkan PCI/vendor IDs; GPU-name family matching is only a presentation fallback.
- Unknown, Khronos/Mesa, or otherwise unmapped identities use the bundled unknown mark rather than a guessed logo.
- Technical tables that contain a report-backed Device/GPU column get an adjacent fixed-width Logo column.

## Driver accent

- Explicit Turnip / third-party driver labels are rendered with the VulkanScope red accent.
- Driver text is escaped before markup is introduced.
- Raw report text is preserved verbatim in content; only matching Turnip / third-party substrings receive a span for visual coloring.

## Security hardening

- Worker POST `/v1/reports` now rejects non-JSON media types with HTTP 415.
- Submission application identity must be `VulkanScope` / `com.efishell.vulkanscope`.
- Submission `collection.status` must be `available`; incomplete reports are rejected with HTTP 409.
- Existing 2 MiB byte limit, schema checks, forbidden personal-identifier field scan, parameterized D1 statements, canonical SHA-256 IDs, HTTPS/CORS behavior and no-IP-storage rule remain.
- Permissions-Policy is tightened for geolocation, camera, microphone, payment and USB.
- A design-consistent 415 static error page is included.

## Performance / usability

- Vendor artwork is reduced from roughly 564 KiB of Android-source PNGs to about 92 KiB of web-local PNGs.
- Images use `loading=lazy` and `decoding=async` and are constrained to a fixed-size frame so table geometry remains stable.
- Existing horizontal table scrollers, touch/trackpad support, filter listboxes, reduced-motion handling and report-detail transition token gate remain unchanged.

## CapsViewer parity review

The current Vulkan Hardware Database source tree still exposes the major categories already represented by VulkanScope Database: reports/devices, Core 1.0-1.4 properties and features, extension properties/features, linear/optimal/buffer formats, memory, queue families, Surface formats/present modes/transforms/composite alpha/usage, instance data, profiles, portability and compare. The 0.33.7 presentation-queue parity fix remains in place. No new category was copied by inference.

## Specification/data-integrity review

- VulkanScope 0.32.5 registry manifest: Vulkan 1.4.360 baseline/header baseline.
- Database canonical/raw handling remains on the 1.4.360 validated producer baseline.
- No new Vulkan enum/flag value is introduced by this UI release.
- Unknown/missing data semantics are unchanged: missing is not unsupported.
