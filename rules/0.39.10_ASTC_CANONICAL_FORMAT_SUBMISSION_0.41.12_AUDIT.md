# VulkanScope Database 0.39.10 / VulkanScope 0.41.12 canonical ASTC format submission audit

## Root cause

The 0.39.9 Worker validated Image Format Properties2 tuple names with `VK_FORMAT_[A-Z0-9_]+`. Vulkan canonical ASTC format tokens contain registry-defined lowercase `x` dimension separators (for example `VK_FORMAT_ASTC_10x8_SRGB_BLOCK` and `VK_FORMAT_ASTC_4x4x3_UNORM_BLOCK_EXT`). Real VulkanScope reports therefore failed the current-producer tuple validator and returned HTTP 400 even though the producer evidence was canonical and complete. The previous synthetic Worker fixture used `VK_FORMAT_S8_UINT`, so it did not exercise this valid-name class.

## Correction

- Tuple-name validation now accepts uppercase Vulkan token characters plus lowercase `x` followed by numeric dimensions inside `VK_FORMAT_*` names.
- The producer is not changed to emit non-canonical spellings; exact Vulkan registry names remain lossless.
- A Worker regression fixture rewrites the complete six-slot tuple group to `VK_FORMAT_ASTC_10x8_SRGB_BLOCK` and requires HTTP 201.
- Malformed tuple identities, duplicate slots, contradictory query states and all existing result/diagnostic cross-checks remain fail-closed.
- Current producer metadata advances to VulkanScope 0.41.12 / 422. Schema 2, technicalReport 3, normalizer 16 and D1 storage remain unchanged.

## Catalog cross-check

VulkanScope 0.41.12's checked-in native format-name table contains 298 canonical `VK_FORMAT_*` tokens. The 0.39.9 uppercase-only grammar rejects 72 of them, all canonical ASTC spellings containing lowercase `x`; the corrected 0.39.10 grammar accepts all 298 while still rejecting non-registry lowercase separators.
