# VulkanScope Database 1.0.19 dominant glow / release-ready publication audit

## Root-cause corrections

1. **Coverage glow:** 1.0.18 attached `.high` to an absolute `ratio >= 0.8` threshold even though the surrounding ranking logic already defined the visually leading state as the greatest count in the row. That made 77.1% / 79.2% dominant values fail to glow while 80%+ values did. 1.0.19 makes glow follow the non-zero `dominant` rank, including ties, while lower non-zero states remain hatched and zero states remain empty.
2. **Premature refresh notice:** 1.0.18 treated Worker `databaseVersion` as frontend publication evidence. A manual Worker deploy could therefore advertise a version before GitHub Release/Pages publication; refreshing repeatedly loaded the old frontend and re-triggered the prompt. 1.0.19 separates live data version metadata from frontend release readiness. The browser polls the same-origin `data/release.json` marker, and Pages is deployed only on a tag after the GitHub Release job succeeds.

## Preserved boundaries

- Live report synchronization remains every 10 seconds plus visibility/focus/online reconciliation.
- No D1 migration, submission schema, technicalReport schema, normalizer, report-ID/hash, registry/header or stored payload semantic changes.
- No dynamic script hot-swap. The refresh action performs cache-busted same-origin navigation.
- Existing CSP, request-body limits, strict UTF-8, privacy rejection, dependency pinning and staged Pages allow-list remain release gates.
