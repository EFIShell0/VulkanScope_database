# VulkanScope Database 0.39.4 tracked-source audit / repository repair

- Database version is 0.39.4; report schema, technicalReport schema, normalizer and VulkanScope producer semantics remain unchanged from 0.39.3.
- GitHub Actions source hygiene must audit Git-tracked repository paths through `git ls-files` when a real checkout is available. The source audit must not recursively inspect repository-owned `.git` metadata.
- Release-ZIP/local fallback may use filesystem traversal, but the repository root `.git` entry must be pruned before traversal. Nested `.git` entries and `.git` symlinks remain invalid source artifacts.
- The normal audit invocation prints its own audit version so an Actions log identifies the exact script that ran even when an older workflow calls the script without `--version`.
- `.github/workflows/pages.yml` must exactly match the checked-in canonical `tools/pages.workflow.yml`. Extra workflow files are stale configuration and fail release verification.
- `tools/repair_repository.py --apply` is the canonical in-place repair path for update-critical hidden workflow files. It replaces the workflow directory and removes stale versioned frontend app JavaScript assets without modifying `.git`.
- Exactly one `assets/app.v*.js` release asset is permitted in the current source tree. Archive extraction does not delete stale files, so stale versioned application JavaScript must be detected and removed explicitly.
- Pages staging uses an exact public asset allow-list. It must not recursively copy the whole source `assets/` directory because stale versioned frontend files left by an in-place archive extraction must never become publicly deployable.
- The staged Pages artifact still allows only the public top-level files/directories declared by the release and only `.nojekyll` as a hidden artifact entry.
- Existing VulkanScope 0.41.5 / Vulkan 1.4.360 producer compatibility, schema 2 / technicalReport 3, normalizer 15, privacy, state semantics, report IDs and D1 data remain unchanged.
- No D1 migration, stored-payload rewrite or report-hash rewrite is required for 0.39.4.
