# VulkanScope Database 1.4.1 address privacy / startup-filter regression audit

Database 1.4.1 succeeds immutable Database 1.4.0 (`c50af2d9597a86a81f6a24c6f1a9208be3bae325a7a9cf1d62894deaf94322ca`). This is a UI/startup correction release: the VulkanScope 1.4.0+ submission floor, report schema, D1 schema, stored payloads, report hashes, normalizer 16 and Vulkan evidence semantics are unchanged.

## Changes audited

- Active address, IPv4, IPv6 and Pseudo IPv4 use separate reveal-state slots. Two rows can display the same transport address without one row's Show/Hide action changing the other.
- The privacy control is presented as a compact glass panel with an opaque grid-style mosaic, blurred underlying text, eye icon and distinct Show/Hide action. Leaving Internet, closing Settings, or receiving a changed observation restores the appropriate masked state.
- Startup filtering is held at the document level: the body starts in `database-loading`, CSS suppresses the entire filter workspace, and the database-loading owner removes the class only after the first committed render. This prevents both native selects and the older ungrouped custom-filter geometry from appearing during preload/report construction.
- Current cache-busted assets are the v1401 JS triplet plus `site.v1401.css`; the v1400 triplet and `site.v1400.css` are the immediate bridge.

## Verification

The release-specific verifier checks independent privacy keys and markup, reset semantics, visual/reduced-motion rules, parse-time/runtime startup-filter ownership, release/cache identity and retention of the VulkanScope 1.4.0 POST floor. Its negative-mutation suite proves that coupled reveal state, missing startup hold, missing filter suppression, stale release markers and privacy-CSS regressions fail the release gate.
