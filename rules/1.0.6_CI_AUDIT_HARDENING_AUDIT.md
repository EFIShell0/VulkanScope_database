# VulkanScope Database 1.0.6 CI/audit hardening audit

## Trigger evidence
The 1.0.5 rollout exposed three independent release-engineering failures rather than a Vulkan report-schema failure:
- Windows local quality-gate Encyclopedia regeneration reported byte drift because the generator wrote text with platform newline translation.
- GitHub Actions invoked the historical 1.0.2 producer-baseline verifier without retained-compatibility mode, so a current Database release was incorrectly required to identify as Database 1.0.2.
- Worker `predeploy` invoked `npm audit` after repository repair intentionally removed the ignored optional lock, producing npm `ENOLOCK` before a security result could be obtained.
The same local npm install also reported the known three-high-severity `sharp <0.35.0` transitive advisory class in Wrangler/Miniflare tooling.

## 1.0.6 corrections
- Encyclopedia output is emitted as explicit UTF-8 bytes with one LF terminator; Windows CI executes the regeneration state-machine gate.
- Canonical CI invokes `verify_1_0_2_producer_baseline.py --skip-version` on later Database releases while retaining all 1.0.2 producer identity/schema checks.
- The documented 1.0.5 stale-lock verifier spelling has a compatibility wrapper instead of a missing-file failure.
- `worker/scripts/security-audit.mjs` creates/refreshes an ignored audit lock before `npm audit`, validates exact Wrangler/sharp resolution+integrity, then runs the high-severity audit fail-closed.
- Wrangler stays exactly 4.130.0. `sharp` is overridden exactly to 0.35.4 rather than using `npm audit fix --force`; reviewed install scripts remain limited to esbuild, sharp and workerd.
- No D1 migration, report rewrite, schema/normalizer change, report-hash change or capability-state change is introduced.

## Packaging-environment evidence boundary
The local packaging environment does not have npm-registry network access, so a fresh network-backed `npm audit` is not claimed here. Static audit wiring, exact pins/override, lock validation and negative-mutation gates are executed locally. Production `predeploy` still fails closed if lock creation/validation or the live high-severity npm audit fails.
