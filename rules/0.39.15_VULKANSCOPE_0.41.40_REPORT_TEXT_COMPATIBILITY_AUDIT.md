# VulkanScope Database 0.39.15 / VulkanScope 0.41.40 report-text compatibility audit

## Immutable baseline
- Predecessor: VulkanScope Database 0.39.14.
- Predecessor ZIP SHA-256: `8405bef9cbe6fc1e2f1c3c5836f3c5c5f3cf612d1afc53313869b204af755777`.
- Current producer audited: VulkanScope 0.41.40 / versionCode 450.
- Vulkan baseline: 1.4.361; submission schema 2; technicalReport schema 3; normalizer 16.

## Demonstrated BUG — valid current report rejected with HTTP 400
VulkanScope 0.41.24 and later separate loader capability from the base-probe instance API in TXT evidence as `Loader API: ...` and `Base probe instance API: ...`. Database 0.39.14 still required the historical merged `Loader / instance API: ...` line. A structurally complete current producer report could therefore fail `validReportText` and return HTTP 400 `[report_text]` even when the JSON envelope and technical report were valid.

0.39.15 makes report-text identity producer-version aware. Producers 0.41.24+ must carry the split loader/base-instance lines and the values must cross-check the current top-level Vulkan envelope. Historical producers keep compatibility with the merged line. The current producer is not weakened to accept the ambiguous merged form.

## Security/correctness invariants
- No report field is dropped, rewritten or truncated to obtain acceptance.
- The fixed HTTPS endpoint, 2 MiB transport ceiling, UTF-8 strict decoding, privacy-field rejection, exact schema checks, D1 canonical SHA-256 identity and chunk storage remain unchanged.
- No D1 migration, schema bump, normalizer bump or historical stored-payload rewrite is required.
- Current health/index producer baseline is updated to VulkanScope 0.41.40 while the canonical Vulkan registry remains 1.4.361.

## Regression evidence
- `tools/test_report_text_identity.mjs --root=<immutable 0.39.14>`: expected FAIL because the predecessor does not implement the producer-version-aware split contract.
- Successor: PASS for 0.41.40 split identity, legacy 0.41.13 merged identity, wrong-instance rejection and unrelated-line rejection.
- Worker end-to-end contract tests require HTTP 201 for a 0.41.40 split report and HTTP 400 for a 0.41.40 report regressed to the merged line.
