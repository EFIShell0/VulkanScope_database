# VulkanScope Database 0.33.6 scroll, error and usability audit

- Native horizontal scrollbar chrome is hidden for technical tables. Every overflowing table is progressively enhanced with local left/right buttons, a draggable/clickable position track, edge fades, keyboard Home/End/Arrow support, and direct touch panning. Raw table content remains a normal overflow container when JavaScript is unavailable.
- Scroll controls must derive enabled/disabled state and thumb position from the actual scrollLeft/clientWidth/scrollWidth values and never obscure table data.
- Custom filter listboxes animate symmetrically when opening and closing; refreshing options must happen before the open class transition so the chevron does not appear pre-rotated.
- Long canonical Vulkan tokens (including Surface present modes) wrap within their cards instead of overflowing or being truncated. Canonical token text is never abbreviated for layout.
- GitHub Pages uses the styled 404.html automatically. Additional static 4xx/5xx pages are included for compatible hosts/routes, and live frontend API-load failures use the same visual language with Reports, GitHub and Retry actions. Worker API responses remain JSON.
- Worker known routes return 405 with an Allow header for unsupported methods instead of a misleading 404. SQL remains parameterized; CSP, no third-party scripts/fonts/analytics, report size limits, schema validation and HTTPS API assumptions remain unchanged.
- CapsViewer parity remains represented across properties/features 1.0-1.4 and extensions, formats, memory, queues, Surface, instance data, profiles, portability and compare. No missing report field is inferred as unsupported.

## Additional regression fixes
- On portrait/mobile layouts the sticky report-detail tabs use an offset below the full two-row top bar and must not overlap navigation.
- Global search caches normalized searchable report text per loaded report and is lightly debounced; this is an optimization only and does not alter matching semantics.
- Enhanced filter menus may open upward when viewport space below is insufficient. The underlying native select remains the state authority.
