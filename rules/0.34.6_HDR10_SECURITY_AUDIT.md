# VulkanScope Database 0.34.6 audit

## HDR10 artwork

The dedicated project-supplied HDR10 SVG is used directly. A white rectangle is embedded in the local sanitized SVG so the original black HDR10 mark remains readable on the dark interface. No HDR10+ crop, clip-path, relabeling or support inference is used.

## Security

- No third-party scripts, fonts, analytics or remote HDR assets were added.
- Existing CSP and JSON-only Worker submission gates remain.
- Browser Origin headers are checked against ALLOWED_ORIGIN; absent Origin remains allowed for the native Android client.
- Report content continues to be escaped before HTML presentation; no eval/new Function/document.write path is introduced.
- D1 queries remain parameterized and report payloads remain bounded to 2 MiB.

## Compatibility

VulkanScope 0.32.7 changes the Turnip SAF picker only; schema-v3 technicalReport data consumed by Database 0.34.6 is unchanged from the compatible 0.32.6 producer model.

## Specification / parity

Database canonical/raw presentation remains producer/registry-driven. HDR logos are not Vulkan capability evidence. The Vulkan Hardware Database reference tree continues to expose reports/devices, core and extension properties/features, formats, memory, queues, WSI/surface, instance, profiles, portability and compare categories already represented by VulkanScope Database.
