# VulkanScope Database 1.4.4 viewport scroll / page-progress audit

- Immutable predecessor: Database 1.4.3, SHA-256 `07d258de359c8fbde49738bbb1799f8f125f4a217f580461a665ce0908d5fa52`.
- Recorded symptom: the far-right viewport thumb appeared almost viewport-height and the top scroll-progress line disappeared after scrolling.
- Root cause: `body.startup-layout-ready #appRoot` retained a startup CSS animation that included `transform`. A transformed ancestor establishes the containing block for descendant fixed-position elements, so `#viewportScrollbar` and `#pageProgress` were resolved against the document-sized app root instead of the browser viewport.
- Correction: the startup reveal is opacity-only. No transform/filter/perspective is applied to the app root. The top progress line is raised above the sticky header while remaining viewport-fixed.
- Existing scrollbar math, native document scrolling, pointer/keyboard controls, mobile geometry, reduced-motion behavior, report data, D1 schema, Vulkan semantics and address privacy behavior are otherwise unchanged.
