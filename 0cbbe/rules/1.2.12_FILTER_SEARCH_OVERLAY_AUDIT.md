# VulkanScope Database 1.2.12 — filter search / overlay audit

## Reproduction
- In a pinned mobile Compare header, opening a report selector placed the centered Minimize control above listbox choices because the dock used z-index 470 while the menu used z-index 460.
- The Settings backdrop used z-index 140 while the pinned Compare shell used z-index 320, so pinned Compare content could remain visually sharp/interactive instead of receiving the Settings dim/blur treatment.
- High-cardinality filter listboxes rendered their complete option arrays, making report/GPU/vendor/token selection unnecessarily long on both desktop and mobile.

## Correction
- Compare listbox open state now propagates to the sticky shell as `.has-select-open`; while present the Minimize/Expand dock is hidden and non-interactive, then restored after the selector closes.
- Settings backdrop/drawer are layered above pinned Compare and viewport chrome, with an 8 px local backdrop blur. Opening Settings closes transient custom listboxes first. Destructive confirmation is layered above Settings.
- Main/detail-workspace custom selectors receive a local search field. The native select remains complete and authoritative; the enhanced listbox filters from the full native option set and mounts at most 50 option buttons at any time. Over-limit and zero-result states are explicit.
- Search/listbox keyboard paths preserve Escape, ArrowDown/Enter, arrows, Home/End, mouse and touch selection behavior.

## Semantics / security
Presentation and bounded-DOM behavior only. No report normalization, support/availability classification, filter values, D1 data, hashes, raw report evidence, producer floor, network request or external dependency changes.
