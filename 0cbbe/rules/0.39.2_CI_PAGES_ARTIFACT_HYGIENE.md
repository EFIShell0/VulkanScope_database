# VulkanScope Database 0.39.2 CI / Pages artifact hygiene audit

## Problem found in 0.39.1

`tools/audit_database.py` recursively inspected the repository root and treated GitHub Actions checkout metadata under the top-level `.git/` directory as if it were part of the deployable release artifact. `actions/checkout` necessarily creates this metadata, so the build job could fail with many `forbidden release artifact .git/...` messages before later checks ran.

## Fix

- Source audit ignores only repository-owned top-level `.git` checkout metadata. Nested `.git` content remains forbidden.
- `tools/build_pages_artifact.py` creates an explicit allow-listed `_site` tree containing only public Pages files.
- `tools/audit_database.py --artifact-tree _site` separately audits the deployable tree and fails closed on `.git`, `.github`, `worker`, `tools`, `rules`, caches, dependencies, binaries, symlinks, unexpected top-level files, or broken local asset references.
- GitHub Actions uploads `_site`, not `.`.

## Compatibility

No D1 migration, report rewrite, schema change, normalizer change, producer-semantic change, or frontend filter/statistics behavior change is introduced. VulkanScope 0.41.5 / schema 2 / technicalReport 3 compatibility remains unchanged.
