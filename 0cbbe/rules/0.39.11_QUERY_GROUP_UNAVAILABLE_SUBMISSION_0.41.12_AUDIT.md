# VulkanScope Database 0.39.11 / VulkanScope 0.41.12 query-group unavailable submission audit

## Trigger

A real VulkanScope 0.41.12 complete-report submission continued to receive HTTP 400 after the canonical ASTC token grammar was fixed in Database 0.39.10.

## Root cause

The producer and Worker disagreed about what constitutes a complete report when the isolated Image Format Properties2 advanced query cannot complete at all.

VulkanScope's project-wide complete-collection rule explicitly permits a scheduled query to finish by producing an explicit `Unavailable` or `Not applicable` result. VulkanScope 0.41.12 follows that rule: when the isolated `imageFormat2` probe is unavailable or times out, it records `Vulkan Query Status / Image Format Properties 2 query = Unavailable: <reason>` and completes collection without fabricating tuple results.

Database 0.39.10 nevertheless applied VulkanScope 0.41.10's per-tuple complete-ledger invariant unconditionally to every 0.41.10+ report. It therefore required Image Format Properties2 query parameters, aggregate diagnostics and a six-slot tuple ledger even when the entire query group had explicitly failed before tuple evidence could exist. This converted a rules-valid explicit Unavailable result into the generic HTTP 400 `Incomplete or invalid VulkanScope submission schema` response.

## Correction

Database 0.39.11 makes the complete-ledger rule conditional on the producer's explicit query-group result:

- `Available` keeps every existing tuple-ledger and diagnostic invariant unchanged.
- `Unavailable: <reason>` is accepted as complete-report evidence only with an empty tuple ledger and no successful Image Format Properties2 or query-diagnostic rows.
- `Not applicable: <reason>` follows the same no-fabrication rule.
- Missing query-group state, malformed state, or contradictions between a group-level unavailable result and tuple/property/diagnostic evidence are rejected fail-closed.

The canonical ASTC lowercase-`x` grammar from 0.39.10 is retained unchanged.

## Regression coverage

Worker contract tests now include an application-shaped VulkanScope 0.41.12 fixture for:

- a complete available Image Format Properties2 ledger;
- an explicit group-level Unavailable result with no fabricated tuple evidence;
- an explicit group-level Not applicable result with no fabricated tuple evidence;
- rejection of an empty ledger with no explicit group state;
- rejection of group-level Unavailable combined with tuple evidence;
- rejection of group-level Unavailable combined with successful Image Format Properties2 property evidence;
- bounded HTTP 400 validation-class feedback.
