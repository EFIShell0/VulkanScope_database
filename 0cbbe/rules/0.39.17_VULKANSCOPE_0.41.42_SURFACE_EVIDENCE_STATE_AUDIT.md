# VulkanScope Database 0.39.17 / VulkanScope 0.41.42 Surface evidence-state audit

## Trigger
A real VulkanScope 0.41.41 HTML/database comparison showed Surface diagnostic booleans such as safety rejection/specification anomaly and a failed historical Surface probe being displayed as Unsupported.

## Immutable predecessor
- VulkanScope-Database-0.39.16.zip
- SHA-256: `0428aff0568bf4124f9cce94c18c951a788b6c0e19a2757d5f172067d1228aed`

## Root cause
Compare used generic support-state classification for `surface.capabilities`, and presentation support used a bare boolean without preserving the owning Surface query status.

## Repair
- Structured and TXT normalization preserve Surface query status/reason.
- Generic Surface capability values use availability semantics.
- Presentation false is Unsupported only under an Available Surface query.
- Presentation queue false is Unsupported only with explicit `queryResult=VK_SUCCESS`; failed or absent query evidence does not become Unsupported.
- Report detail and Surface aggregate cards use the same state helpers as Compare.

## Failing-before-fix
`node tools/test_surface_compare_04142.mjs <immutable 0.39.16>`: expected FAIL.

## Successor
The same behavioral contract passes on 0.39.17. Negative mutations reject bare boolean presentation classification, generic Surface semanticStatus classification, and loss of queryStatus normalization.

## Unchanged contracts
D1 schema, canonical report hashing, stored bytes, normalizer 16, Worker validation, privacy/CORS, UTF-8 limits and 2 MiB transport remain unchanged. No migration is required.
