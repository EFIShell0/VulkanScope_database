# VulkanScope Database 1.3.5 Submitted time-zone wrapping audit

Database 1.3.5 is a presentation-only successor to immutable Database 1.3.4 (`b64d7ac3a8b20e3a3613f4b64db0a806486bc4fdbc2c3840f86d86c7c20128b0`). D1 schema/migrations, stored report payload bytes/hashes, report IDs, normalizer 16, Vulkan 1.4.362/header 362, VulkanScope 1.2.5 submission floor and validated browser floors are unchanged.

Mandatory checks:

- Reports Submitted Date, Time and Time zone continue to derive exclusively from the server-authored `submitted_at` instant and the existing regional presentation state. No timestamp storage, sorting, age-filter or Compare identity semantics change.
- The Time zone value must be allowed to wrap. The historical broad `.submitted-stack span{white-space:nowrap}` rule must not force the third Submitted value back onto one line.
- When the regional seasonal override adds `Daylight / summer offset` or `Standard / winter offset`, that seasonal descriptor is rendered as a dedicated second line beneath the zone/UTC-offset portion. The visible wording remains unchanged; only layout is changed.
- Long IANA time-zone names remain complete and readable with safe wrapping; no ellipsis, clipping, abbreviation or data rewrite is allowed.
- Date and Time remain single-line values. Submitted disclosure width/animation, server-authoritative timestamp source, custom table scrolling and reduced-motion behavior remain unchanged.
- Existing 1.3.4 demand-driven filter-scrollbar behavior and Compare chevron semantics remain intact.
- Browser-visible identity advances to 1.3.5 / cache key 1305. Pages stages only the immediate immutable 1.3.4 frontend triplet beside the 1.3.5 triplet during propagation.
- `tools/verify_1_3_5_submitted_timezone_wrap.py` and its negative-mutation suite are mandatory release gates. Immutable 1.3.4 regression verification, Worker contract checks, D1 migration replay, source/Pages audits and deterministic strict packaging must pass.
- No D1 migration is required for 1.3.5.
