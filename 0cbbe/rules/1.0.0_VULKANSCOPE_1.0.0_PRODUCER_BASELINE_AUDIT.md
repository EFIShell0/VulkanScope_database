## Demonstrated gap
The 0.39.27 producer parser accepts only `0.x.y` application versions. A schema-compatible VulkanScope 1.0.0 producer would therefore be rejected before the established 0.80.10+ Vulkan 1.4.362 validation contract could run.

## Repair
The producer parser now accepts canonical three-component semantic versions across major-version boundaries and evaluates existing semantic gates with explicit version ordering. VulkanScope 1.0.0 is current and requires versionCode 1000. Historical 0.80.x and 0.41.x mappings remain unchanged. No capability, registry or stored report is normalized to obtain acceptance.

## Non-regression
Registry baseline remains exact `Vulkan 1.4.362`; submission schema, technicalReport schema, normalizer, D1 storage, hashes, payload chunking, privacy/security ceilings, loading/Encyclopedia UI and reference corpus remain unchanged.
