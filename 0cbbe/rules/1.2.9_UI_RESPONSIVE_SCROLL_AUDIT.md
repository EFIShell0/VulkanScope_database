# VulkanScope Database 1.2.9 UI / responsive / scrollbar audit

## Scope
This release is presentation and interaction hardening over immutable Database 1.2.8. No report schema, D1 migration, normalizer, canonical state semantics, producer floor, report identity or stored-payload behavior is changed.

## Browser compatibility gate
- `#browserCompatibilityGate` is emitted with `hidden` in `index.html`; a supported browser therefore cannot display the warning during parse/paint before the compatibility script runs.
- `browser-compat.v1209.js` retains Chromium 84+, Firefox 86+, Safari 14.1+ plus required Web Platform feature checks. Only the failed branch removes `hidden` from the gate; only the successful branch removes `hidden` from `#appRoot`.

## Reports filter parity and mobile containment
- `organizeGlobalFilters()` now excludes only Encyclopedia, so Reports consumes the existing `FILTER_FAMILIES` source of truth instead of its legacy flat selector row.
- Reports Sort / Per page are grouped in the same `filter-family` design language while retaining the original native `select` elements as authoritative state.
- <=760 px forces Reports filter families, clear control, toolbar group and enhanced listbox controls to `minmax(0,1fr)` / 100% widths. No 190/220 px minimum survives on the Reports mobile path.

## Compare fixed-follow minimization
- The 1.2.8 explicit fixed shell/sentinel/flow-placeholder mechanism remains intact.
- The new centered `#compareMinimizeToggle` exists only as useful chrome while the shell is pinned. It toggles `.is-minimized`; the compact A/B strip reads current GPU names directly from the authoritative selected report objects each time `go()` runs.
- Clearing pinned geometry removes `.is-minimized`, restores the button state and hides the mini strip, so returning to the top always restores the normal comparison workspace.
- Pinned width uses the live viewport/page rectangle without the previous 260 px hard minimum. <=760 px also overrides the prior three-column compact report grid to a single column.

## In-panel scrollbar parity
- `enhanceSurfaceScrollbar()` covers `.settings-drawer-body`, `.custom-select-menu`, `.coverage-report-dialog-body` and `.modal-paged-list`.
- Rail buttons/track/thumb deliberately reuse `viewport-scrollbar-arrow`, `viewport-scrollbar-track` and `viewport-scrollbar-thumb` classes, preserving the same appearance and focus language.
- Host metrics use `clientHeight`, `scrollHeight` and `scrollTop`; thumb dragging writes only `host.scrollTop`, arrows/track use host scrolling, and keyboard controls mirror the viewport rail.
- One shared document MutationObserver plus resize scheduling synchronizes dynamic surfaces; the implementation does not create per-option/per-row MutationObservers or polling intervals.

## Regression invariants
- Database/Worker/frontend release identity: 1.2.9; app/browser assets and cache key: 1209.
- Schema 2, technical report 3, normalizer 16, Vulkan 1.4.362/header 362, producer/query baseline and VulkanScope 1.2.5 POST floor are unchanged.
- Existing supported/unsupported/available/unavailable/unknown semantics and raw evidence remain untouched.
- Reduced-motion coverage includes new rail/minimize transitions.
