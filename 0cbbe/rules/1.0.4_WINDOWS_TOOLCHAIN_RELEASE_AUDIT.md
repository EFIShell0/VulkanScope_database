# VulkanScope Database 1.0.4 — Windows / toolchain / release audit

## Scope
This release is a release-engineering and dependency-hardening successor to Database 1.0.3. It does not change report evidence semantics, D1 storage, report identifiers/hashes, the preload/live-delta model, schema 2, technicalReport schema 3, normalizer 16, or the VulkanScope 1.0.15 / 1015 producer contract.

## Windows regression
The 1.0.3 deployment log exposed a real Windows-only tooling defect: path-sensitive Node ESM tests derived the repository path from `new URL(import.meta.url).pathname`, causing `path.resolve()` to form a doubled drive path such as `C:\C:\Users\...\assets`. The four affected Compare/Surface test files now use Node's canonical `fileURLToPath(import.meta.url)` conversion.

The canonical Pages workflow adds a `windows-latest` prerequisite job that executes these path-sensitive tests. The Linux build depends on that job, so a future Windows path regression blocks Pages deployment and tag release instead of being hidden by Linux-only CI.

## Worker toolchain security
Wrangler is pinned exactly to 4.130.0. The Worker package records explicit npm install-script approvals for the reviewed toolchain packages `esbuild`, `sharp`, and `workerd`; blanket script approval is not used. `predeploy` now runs both the pinned Cloudflare account verifier and `npm audit --audit-level=high`, so high/critical npm advisories block production deployment. No `npm audit fix --force` downgrade path is part of the release process.

`worker/package-lock.json` remains optional local deployment state and is not a release-package requirement. When present, the existing optional-lock verifier requires Wrangler 4.130.0 and package integrity metadata.

## GitHub Release reliability
The canonical workflow also handles `v*` tags. After the same mandatory build gates pass, a GitHub-hosted release job builds the deterministic release archive and uses the runner-provided GitHub CLI with the scoped `github.token`. Local `gh` installation is therefore no longer required. A rerun uploads the release assets with `--clobber` instead of failing because a release already exists.

## Packaging
`tools/package_release.py` first enforces repository repair/check and strict immutable-predecessor regression verification, then packages exactly the contract-owned release tree. Local/generated workspace state, including an optional `worker/package-lock.json`, is excluded. ZIP entries are sorted and use a fixed 1980-01-01 timestamp; SHA-256 is emitted as a sidecar rather than embedded self-referentially.

## Evidence gates
The release adds two mandatory gates:
- `tools/verify_1_0_4_windows_toolchain_release.py`
- `tools/test_1_0_4_windows_toolchain_release_negative_mutations.py`

The negative suite covers Windows-unsafe URL path conversion, release-job removal, stale cache identity, stale Wrangler pin, and loss of reviewed install-script policy.

## Storage / compatibility boundary
No D1 migration, stored-report rewrite, report-ID/hash rewrite, schema bump, normalizer bump, producer-floor change, Vulkan registry/corpus change, or evidence-state inference change is introduced by Database 1.0.4.
