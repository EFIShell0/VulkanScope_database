# VulkanScope Database 1.0.5 optional-lock overlay audit

## Observed failure
The 1.0.4 GitHub build reached `Verify optional npm lock` after repository repair and failed because the repository still contained an old tracked `worker/package-lock.json`. The lock root recorded Wrangler `^4.125.0` and the resolved package recorded 4.125.0, while the 1.0.4 canonical Worker source and verifier required exact Wrangler 4.130.0. `.gitignore` does not retroactively untrack a file already present in Git history, so a normal ZIP overlay could leave that stale lock in the long-lived repository.

## 1.0.5 correction
The canonical repository repair now purges an existing ignored `worker/package-lock.json` during `--apply`. The release package continues to exclude this optional local state. The optional-lock verifier independently checks canonical `worker/package.json` for exact Wrangler 4.130.0 even when no lock is present; if a lock is present in another workspace, the verifier still requires exact 4.130.0 lock metadata and integrity and fails stale locks with a repair instruction.

The existing-repository overlay fixture now creates the exact stale 4.125.0 tracked-but-ignored lock shape, verifies it fails before repair, applies repository repair, verifies the lock is gone, then continues immutable source-overlay/strict-package checks. This prevents the regression from being hidden by a permissive lock verifier.

## Unchanged contracts
VulkanScope 1.0.15 / 1015 compatibility, Vulkan 1.4.362 registry/header evidence, schema 2, technicalReport 3, normalizer 16, D1 migrations, report hashes, preload/live-delta behavior, security boundaries and Worker API semantics are unchanged. No D1 migration or stored payload rewrite is required.
