# VulkanScope Database 1.4.11 — VulkanScope 3.0.2 compatibility audit

Database 1.4.11 succeeds immutable Database 1.4.10 (ZIP SHA-256 `c52ff548c05745d6a9e4c439406afe42179bc7a430f9df78772e0a4eb29750d0`). This release raises only the new-submission producer boundary and release-authored producer metadata while preserving historical reads, D1 storage, report identity, normalizer 16 and Vulkan 1.4.364 evidence semantics.

## New-report producer floor
- `POST /v1/reports` accepts VulkanScope 3.0.2 / versionCode 3002 at the floor and rejects VulkanScope 3.0.1 and all lower semantic versions before generic envelope validation.
- The 3.x identity mapping is fail-closed: `versionCode = 3000 + minor*100 + patch`. Unknown future major versions are not guessed.
- The floor is POST-only. Historical reports from 2.x/1.x/0.x remain readable through existing GET/list/Compare paths without payload, timestamp, ID or hash mutation.

## VulkanScope 3.0.2 compatibility
- The application 3.0.2 source uses versionCode 3002, submission schema 2, technicalReport schema 3, Vulkan 1.4.364 registry/header evidence and the existing exact device environment fields.
- Worker validation keeps the 2 MiB transport ceiling, complete-report requirements, exact envelope checks, sensitive-key rejection, UTF-8 bounds, canonical hashing and current technicalReport/query semantics.
- No D1 migration or normalizer increment is required.

## Release metadata / cache boundary
- Pages, preload and Worker metadata pin `VulkanScope 3.0.2 · Vulkan 1.4.364` and `VulkanScope 3.0.2+ · schema 2 / technical report 3`.
- Current browser assets are v1411/cache 1411. The v1410 app/browser/release-bootstrap triplet is retained as the immediate cache bridge; v1409 JavaScript is removed from the strict package.
- Encyclopedia registry data remains Vulkan 1.4.364 / 477 extensions; only its producer appVersion metadata advances to 3.0.2.
- Pages publication does not deploy the Cloudflare Worker. Production enforcement requires an explicit successful Worker deployment.
