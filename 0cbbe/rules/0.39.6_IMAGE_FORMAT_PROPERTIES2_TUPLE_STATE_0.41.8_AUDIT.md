# VulkanScope Database 0.39.6 Image Format Properties2 tuple-state / VulkanScope 0.41.8 audit

## Trigger
A live 0.35.1 versus 0.41.7 comparison showed an old AVAILABLE Android Hardware Buffer tuple against UNKNOWN / Not reported even after the 0.41.7 collector started executing external queries independently.

## Root cause
0.41.7 preserved negative Image Format Properties2 results only in aggregate counters. Tuple identity was absent from detailedProperties, so Database could not distinguish queried unsupported/unavailable from never reported.

## Correction
VulkanScope 0.41.8 emits exact tuple-level negative values. Database keeps `availabilityStatus` semantics for Properties query coverage, but Compare derives the stronger tuple capability state from the explicit value: exact `Unsupported: VK_ERROR_FORMAT_NOT_SUPPORTED` becomes Unsupported, while `Unavailable: VkResult=<n>` remains Unavailable. Historical successful rows use the same key and compare directly.

## Validation
The Worker accepts the exact 0.41.8 tuple forms and rejects fabricated/malformed current-producer tuple status text. The compare contract explicitly verifies AVAILABLE versus UNSUPPORTED for the same S8/AHB key.

## Compatibility
Schema 2, technicalReport 3, normalizer 15, D1 schema, existing report hashes and the 0.32.4+ compatibility floor are unchanged.
