# VulkanScope Database 0.39.5 cross-producer compare / VulkanScope 0.41.7 audit

## Trigger
A live comparison between VulkanScope 0.41.3 and 0.41.6 Turnip reports showed valid driver differences mixed with collector/evaluator-version differences. The same profile evaluation also appeared twice as `PROFILES` and `VULKAN PROFILES`.

## Root causes
- `compareMap()` imported legacy `VULKAN PROFILES` capability rows and separately imported normalized `profiles`, duplicating the same evidence.
- Legacy profile keys included revision in the row identity, so a profile revision update appeared as removed/added rows rather than the same profile evaluated against a different revision.
- Compare had no explicit cross-producer warning and no way to limit the view to evidence present in both reports.

## Correction
- Normalized `profiles` is authoritative. Legacy `VULKAN PROFILES` rows are fallback-only when normalized profile evidence is absent.
- Profile row identity is canonical profile name; revision is retained in the value.
- Compare detects producer-version/versionCode differences and explains that one-sided fields can reflect collector/query or evaluator changes.
- `Common evidence only` is a presentation filter; it does not alter stored report evidence.
- Differing profile revisions are explicitly called out as non-equivalent evaluation definitions.

## Compatibility
Submission schema 2, technicalReport 3, normalizer 15, report IDs, D1 schema and the compatibility floor remain unchanged. Current producer metadata advances to VulkanScope 0.41.7 / 417 while historical compatible reports remain accepted.
